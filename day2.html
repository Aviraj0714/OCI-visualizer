03Security Fundamentals

Zero Trust

"Never trust, always verify." Every request is authenticated and authorized, regardless of network location.

Click play to step through Zero Trust evaluation for a single access request.

Traditional (perimeter) model

Trust is granted once inside the network boundary — a VPN login unlocks broad access.

Zero Trust model

Every request re-verifies identity, device posture, and risk — regardless of network location, every time.

06Cloud Guard

Cloud Guard Architecture

Cloud Guard continuously watches your targets, evaluates them against detector recipes, and can automatically respond.

🎯 Targets

The compartments/tenancy Cloud Guard monitors.

🧪 Detector Recipes

Rules that flag misconfigurations, risky activity, or threats.

🤖 Responder Recipes

Automated or manual actions taken when a problem is detected.

📋 Managed Lists

Reusable allow/deny lists (IPs, tags) referenced by detector rules.

12Cloud Guard

Where Should Cloud Guard Be Enabled?

A decision exercise: root tenancy vs. individual compartment.

Do you need consistent, tenancy-wide visibility with minimal ongoing maintenance?
✅ Enable Cloud Guard at the root/tenancy level. Advantage: single recipe set, nothing falls through the cracks. Disadvantage: less granular tuning per team.
✅ Enable Cloud Guard at the compartment level. Advantage: tailored detector/responder recipes per team. Disadvantage: more overhead to maintain consistency across compartments.

28Wrap-Up

Cheat Sheets

Security

  • CIA = Confidentiality, Integrity, Availability
  • Defense in Depth = layered, independent controls
  • Zero Trust = never trust, always verify

Cloud Guard

  • Detectors find problems, Responders act on them
  • Security Zones block; Cloud Guard detects+responds
  • Lifecycle: Resource → Detection → Problem → Investigation → Remediation → Closed

Cost Management

  • Budgets alert at a % threshold, they don't hard-stop spend
  • BYOL saves money if you already hold active-support licenses

Governance

  • Limits = provider ceiling (needs a support request to raise)
  • Quotas = self-imposed cap within a compartment
  • Organization Mgmt links tenancies for billing, not IAM
