02Encryption Fundamentals

Symmetric Encryption

One key both encrypts and decrypts — fast, but both parties must already share that same secret key.

AES

The modern standard — AES-256 is what OCI uses for encryption at rest.

DES

Legacy 56-bit cipher, broken by brute force — historical interest only.

3DES

Triple-applied DES, slow, being phased out industry-wide.

ChaCha20

A fast modern stream cipher, popular in TLS on mobile/low-power devices.

03Encryption Fundamentals

Asymmetric Encryption

Two mathematically linked keys — a public key anyone can use to encrypt, and a private key only you hold to decrypt.

RSA

Based on the difficulty of factoring large primes — widely used for key exchange and signatures.

ECC

Elliptic Curve Cryptography — equivalent security to RSA with much smaller keys, faster.

05Encryption Fundamentals

Encryption at Rest

Every OCI storage service is encrypted at rest by default, using AES-256.

💽 Block Volume

Encrypted transparently before data ever touches disk.

📦 Object Storage

Every object encrypted server-side automatically.

🗄 Database

Transparent Data Encryption (TDE) protects data files at rest.

💾 Boot Volume

The OS disk itself is encrypted from first boot.

🎓
Exam TipOCI encrypts everything at rest by default using Oracle-managed keys — using your own Vault key is optional, for when you need control over rotation, disablement, and audit of the encryption key itself.
06Encryption Fundamentals

Encryption in Transit & the TLS Handshake

Data moving across a network is protected by TLS, which combines both encryption types you just learned.

Asymmetric crypto establishes trust and exchanges a session key; symmetric crypto (fast) encrypts the actual data.

07Encryption Fundamentals

Hybrid Encryption

Real systems (including OCI Vault) combine both: asymmetric to protect a small key, symmetric to protect the actual data.

🎓
Exam TipThis exact pattern is called envelope encryption — OCI Vault's Master Encryption Key never directly encrypts your data; it encrypts a Data Encryption Key, which does the bulk work.

11OCI Vault & KMS

Vault & KMS Architecture

OCI Vault is the managed service; KMS is the underlying key management engine behind it.

Vault

A logical container for your keys and secrets, backed by dedicated or shared HSM partitions.

Master Encryption Key (MEK)

The root key you manage — never leaves the Vault/HSM in plaintext.

Data Encryption Key (DEK)

A key generated per operation, encrypted ("wrapped") by the MEK — this is envelope encryption in practice.

Secrets

Arbitrary sensitive values (passwords, tokens) stored and versioned inside the Vault, separate from keys.

12OCI Vault & KMS

HSM & Key Protection Modes

A Hardware Security Module is tamper-resistant hardware that generates and stores keys — they're designed so the key material can never be extracted, even by the operator.

ModeWhere the key livesUse when
Software ProtectedSoftware, in a shared multi-tenant KMSLower cost, standard workloads
Virtual Private VaultDedicated partition on shared HSM hardwareNeed isolation but not a fully dedicated HSM
HSM ProtectedFIPS 140-2 Level 3 validated HSMStrict compliance (PCI DSS, HIPAA) requiring hardware-backed keys

16Secrets Management

Secret Versions & Rotation

Rotating a secret creates a new version — old versions can stay valid briefly so in-flight processes don't break.

17Secrets Management

Key Rotation Timeline

Three rotation models, same underlying mechanism: a new key version is created, old data can still be decrypted by prior versions.

Manual Rotation

An admin explicitly triggers rotation, on demand.

Scheduled Rotation

Rotates automatically on a fixed calendar interval (e.g. every 90 days).

Automatic Rotation

Fully managed rotation, often tied to application-integrated secret rotation (e.g. database password + secret updated together).

18Secrets Management

Application Integration

An application retrieves a secret at runtime, authenticating itself first — never hardcoding the value.

31Certification Center

Cheat Sheets

Encryption

  • Symmetric = 1 key, fast, hard to distribute
  • Asymmetric = key pair, slow, easy to distribute
  • Envelope encryption = MEK wraps a DEK, DEK encrypts data

PKI

  • Root CA → Intermediate CA → Leaf certificate
  • Browsers trust the Root, not the leaf directly
  • Missing intermediate = common "untrusted" error

Vault & KMS

  • Software / VPV / HSM protection modes
  • Scheduled deletion has a 7-30 day mandatory wait
  • HSM = FIPS 140-2 Level 3 tamper-resistant hardware

Secrets

  • Rotation creates a new version, doesn't destroy old ones immediately
  • Never hardcode — retrieve at runtime with an authenticated principal
  • Cross-region replication protects against regional failure
