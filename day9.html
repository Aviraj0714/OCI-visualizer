👁 Observability Foundations

⏱ 25 minFoundationalExam Weight: High
Learning Objectives
  • Distinguish monitoring (watching known signals) from observability (being able to ask new questions of the system).
  • Name the three observability pillars — metrics, logs, traces — and what each answers.
  • Distinguish health monitoring from business monitoring.
Prerequisite: none — this is lesson one
🚗
Real-World Analogy

Monitoring is a car's dashboard: fixed gauges for speed, fuel, and temperature. Observability is popping the hood with a diagnostic scanner — you can ask a question nobody built a gauge for, like "why does the engine hesitate only above 3,000 RPM in cold weather?"

Telemetry is the raw material of observability, expressed as three complementary signal types: metrics (numeric time series — "how much, how fast"), logs (discrete timestamped events — "what exactly happened"), and traces (the path a single request took across services — "where did the time go"). OCI Day 9 focuses on metrics and logs in depth, with traces covered at the concept level.

Visualizer › The Three Pillars
📊 Metrics

"CPU is at 92%." Cheap to store, great for trends and alarms, but low detail.

📜 Logs

"09:14:02 ERROR: connection pool exhausted." Rich detail, more expensive to store at scale.

🔗 Traces

"Request X spent 340ms in the payment service, 12ms everywhere else." Shows where time went across a distributed call.

Health Monitoring vs. Business Monitoring ▼
Health Monitoring asks "is the infrastructure working?" (CPU, memory, disk, is the instance up). Business Monitoring asks "is the business succeeding?" (checkout completion rate, orders per minute, revenue per hour). A system can be perfectly healthy while the business metric that matters — successful checkouts — silently drops to zero because of a broken payment integration nobody's infrastructure alarm would ever catch.
🎯
Exam Tip

If a question describes debugging why something is slow across multiple services, the answer involves traces. If it is about whether something is slow right now, that is a metric. If it is about exactly what happened at a specific moment, that is a log.

Exam Tip

⚠
Common Trap

Dimensions are what let you scope a metric down to ONE resource instead of an aggregate of everything in a compartment — forgetting a dimension filter is the most common reason an MQL query returns a confusing blended result.

ƒ Common MQL Functions

  
⏱ 25 minCore ConceptExam Weight: High

  
Learning Objectives
  • Choose the right aggregation function for a given operational question.

  
Prerequisite: MQL Playground


  

    
FunctionAnswers

    
mean()"What's the typical value?" — smooths noise

    
max()"What's the worst it got?" — surfaces spikes

    
min()"What's the best/lowest it got?"

    
sum()"What's the total across all matched resources?"

    
count()"How many data points/resources reported?"

    
rate()"How fast is this changing per unit time?"

    
percentile(.99)"What did the worst 1% of requests experience?"

    
Moving average"What's the underlying trend, ignoring short-term noise?"

  


  
⚠
Common Trap
Averages hide outliers. A mean() latency of 80ms can hide a p99 of 4,000ms affecting 1% of users badly — certification scenarios frequently test whether you'd reach for percentile() instead of mean() for a "some users are complaining" investigation.

🛡 Audit Architecture

  
⏱ 20 minCore ServiceExam Weight: High

  
Learning Objectives
    
    
  • Explain why Audit logging is automatic and cannot be disabled.
    • 
    
  • Name what a single audit event records.
    • 
  

  

  
Prerequisite: Module 5 complete


  
📜
Real-World Analogy
Audit is a building's key-card log — every door opened, by whom, and when, recorded automatically whether or not anyone asked for it. You cannot turn off the key-card system just because you would rather not be tracked.


  
OCI Audit automatically records every API call made against your tenancy — who (principal), what (operation), on which resource, from where, and when. This happens by default for every tenancy and cannot be disabled, making it the foundational tool for security investigation and compliance.

🎯
Exam Tip
Audit records the console, CLI, SDK, and Terraform actions equally — anything that ultimately calls an OCI API is captured, regardless of which tool initiated it.

Dashboard Poster
A dashboard = layout + a set of MQL-backed widgets. It stores no data itself.

  
Alarm Lifecycle Poster
OK → Pending (breach sustained) → Firing → Acknowledged → Resolved

  
Notification Poster
Topic (broadcast) → Subscriptions (Email/Slack/PagerDuty/Webhook, each must be confirmed) → Delivery with retries

  

    
CategorySource

    
ServiceAutomatic, from OCI services

    
CustomYour applications

    
AuditAutomatic API call record, always on

  

  
Connector Hub Poster
Logging/Monitoring/Streaming → Connector Hub → Streaming / Object Storage / Functions

  
Audit Poster
Always on, cannot be disabled. Records principal, operation, resource, source IP, timestamp, result.

  
Incident Response Poster
Detection → Triage → Containment → Mitigation → Recovery → Postmortem (blameless)

  
Capacity Planning Poster
Proactive trend forecasting complements, never replaces, reactive alarms.
